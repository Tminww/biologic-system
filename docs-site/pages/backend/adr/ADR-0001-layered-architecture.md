# ADR-0001: Слоистая архитектура и правила зависимостей

- Status: Accepted
- Date: 2026-02-16

## Context

Нужно получить предсказуемую структуру FastAPI-проекта с высокой тестируемостью и понятными зонами ответственности.

## Decision

Принять слоистую архитектуру:

1. API layer
2. Service layer
3. Repository layer
4. Model/Schema layers

Дополнительно:

- Вынести `create_app` в отдельный модуль.
- Централизовать ошибки и handlers в `core`.
- Использовать DI FastAPI через `Depends`.

## Consequences

Плюсы:

- Ясные границы и удобство модульного тестирования.
- Более простая замена реализации инфраструктурных частей.

Минусы:

- Больше шаблонного кода для простых CRUD.
