# Архитектура

## Цели архитектуры

- Единый подход к CRUD-модулям
- Явный контроль доступа на UI и уровне роутера
- Простая интеграция с backend на сессионной авторизации
- Минимум магии и предсказуемая структура

## Архитектурные слои

- `app`: bootstrap приложения, PrimeVue, hooks API, router
- `layouts`: `AuthLayout` и `MainLayout`
- `modules`: бизнес-фичи (страницы, API, диалоги)
- `shared`: переиспользуемые компоненты, composables, типы, API client
- `styles`: тема и глобальные стили

## Паттерн модуля

Стандартный CRUD-модуль строится из трех частей:

1. API слой (`*.api.ts`)
2. Страница (`*Page.vue`) с `BaseTable` и `useServerTable`
3. Диалог (`*Dialog.vue` или `CatalogDialog.vue`) с `useCrudDialog`

Дополнительно:

- `useOptimistic` для update/delete
- `useConfirmDelete` для подтверждения удаления
- `useDialogHash` и `useTableHash` для deep-linking через `#hash`

## Схема данных и потока

1. Страница собирает `filters/pagination/sort`
2. `useServerTable` сериализует их в query params
3. API client отправляет запрос с `credentials: 'include'`
4. Ответ кладется в реактивные `data/total`
5. UI таблицы рендерит строки и action-кнопки с проверкой прав

## Отображение идентификаторов в таблицах

1. Технический `id`/`uuid` используется в API, `dataKey` и CRUD-операциях, но не отображается пользователю как значение колонки.
2. В колонке `№` отображается клиентский порядковый номер строки.
3. Формула номера: `offset + rowIndex + 1` (в текущей реализации через состояние пагинации таблицы).
4. Этот номер не является постоянным идентификатором и может меняться при сортировке, фильтрации и пагинации.
5. Backend не генерирует отдельный пользовательский порядковый номер для таблиц.

## Ошибки и реакции

- `401`: локальный logout и редирект на `/login`
- `403`: toast об ошибке прав
- `409 STALE_DATA` для объектов: предупреждение + `refresh()`

Обработка `401/403` централизована через `setApiHooks` в `src/app/main.ts`.
